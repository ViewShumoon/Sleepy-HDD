# 自行起转靠手动重新休眠应对，不做状态检测与自动再休眠

受管磁盘在软件视角处于休眠/离线时可能自行起转（实测路径：盘自行启动，卷锁未被破坏、资源管理器访问仍提示"磁盘未就绪"），此时 UI 按钮为"唤醒"，用户须先唤醒再休眠两次点击。决策：不检测、不自动——把"休眠/离线"对已处于目标态的盘重定义为**重新停转/重新置属性**：只重发 STANDBY IMMEDIATE（离线再补置离线属性），跳过锁卷/卸载/CACHE FLUSH（后者会使沉睡盘起转）；休眠↔离线互转同样先重发停转（消除自行起转造成的停转歧义），使任意一次休眠/离线点击都让盘停转；"全部休眠/全部离线"全局按钮因此成为一次点击的再休眠入口。自行起转不做任何检测：唯一可靠的被动手段是周期轮询 ATA CHECK POWER MODE（0xE5，规范保证不起转），代价是固件兼容风险与范围扩张。

Considered options: 0xE5 轮询检测 + 自动再休眠 + 循环保护（被否：唤醒源持续时启停循环磨损大于放任旋转；突破 v1"不做自动休眠"边界；个别固件对 0xE5 行为异常）；WM_POWERBROADCAST 恢复事件定向再休眠（被否：实测唤醒路径是盘自行起转，非系统睡眠恢复）；徽章显示真实状态（被否：无检测则无从知道，徽章维持软件视角）。

Consequences: 交互契约是"怀疑起转即可点一次全部休眠/离线，点了无害"——对真沉睡盘重发 STANDBY IMMEDIATE 不起转，正确性靠幂等而非状态感知；徽章可能在盘旋转时仍显示"休眠"，接受。定时策略与全局按钮共用同一重新断言语义（到点对已休眠盘重发停转，同样无害）；卡片单按钮切换（Q19-A）与唤醒流程不变。
