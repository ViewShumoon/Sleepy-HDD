# Sleepy HDD v1 真机手测清单

票 #12 交付物：覆盖自动化测试无法触及的 UI 与真硬件行为（DESIGN.md 第 5 节测试策略）。
每个条目为"步骤 + 预期结果"，验证通过后勾选。术语遵循 [GLOSSARY.md](../../GLOSSARY.md)：
在线 / 休眠 / 离线 / 受限 / 唤醒 / 默认动作 / 受管磁盘 / 定时策略。

## 前置条件

- [ ] 一台 Windows 11 x64 真机（仅支持 Windows 11，见 ADR-0004）。
- [ ] 至少一块内置固定机械硬盘（SATA/ATA/SCSI 总线）作为受管磁盘；建议另备 USB 移动硬盘与 NVMe/SSD 各一，用于验证排除项。
- [ ] x64 发布产物（`dotnet publish src/SleepyHDD.App -c Release -p:Platform=x64 -r win-x64 --self-contained true` 的输出目录，见下文"发布产物验证"）。
- [ ] 测试数据风险提示：休眠/离线会拒绝或中断对目标卷的访问，请在非关键数据卷上测试，重要数据先备份。
- [ ] 记录状态文件位置备用：`%LOCALAPPDATA%\SleepyHDD\state.json`（按磁盘序列号记录休眠/离线在案盘）；设置文件同目录 `settings.json`。

## 0. 启动形态与全局

- [ ] 双击发布产物中的 `SleepyHDD.App.exe` → 触发 UAC 提权确认（应用清单 `requireAdministrator`，ADR-0003）；确认后主窗口打开，标题"Sleepy HDD"。
- [ ] 应用已运行时再次启动 exe → 不产生第二个托盘图标/窗口，已运行的主实例窗口被聚焦激活（单实例 `AppInstance.FindOrRegisterForKey`）。
- [ ] 本机已装 Windows App Runtime 时启动 → 无任何弹窗提示，直接进入应用。

## 1. 枚举与分类

- [ ] 主窗口显示"受管磁盘"标题，每块内置机械盘一张卡片：型号（无型号时显示"磁盘 #盘号"）、容量文本、卷列表（盘符 + 卷标 + "已用 X / 共 Y"用量）、状态徽章为绿色"在线"。
- [ ] USB 移动硬盘不出现在卡片列表中（总线排除）。
- [ ] NVMe/SSD 不出现在列表中（寻道惩罚判定排除；SeekPenalty 无法判定时按型号含 "SSD" 兜底）。
- [ ] 卡片按物理盘编号升序排列。
- [ ] 机器上没有任何受管磁盘时 → 显示空态图标与文案"未发现受管的机械硬盘"。
- [ ] 热插拔：运行中接入一块受管机械盘 → 无需重启应用，卡片实时出现，同时托盘通知"磁盘已接入 · 型号"（信息级）。
- [ ] 热插拔：移除该盘 → 卡片实时消失，托盘通知"磁盘已移除 · 型号"。

## 2. 三态转换与保护模式

- [ ] 在线 → 休眠：点击卡片动作按钮"休眠"（默认动作为休眠时）→ 徽章变黄色"休眠"，按钮变为"唤醒"；转换期间按钮禁用，同盘重复点击无效。
- [ ] 保护模式：盘处于休眠后，打开"此电脑"→ 该盘盘符仍然可见；双击盘符或经命令行访问该盘文件 → 返回"拒绝访问"错误，磁盘保持停转（听不到起转声），应用徽章保持"休眠"。
- [ ] 休眠 → 离线：对已休眠的盘点击顶栏"全部离线"（默认动作为离线时）→ 徽章变灰色"离线"，该盘卷（盘符）从资源管理器/系统中完全消失。
- [ ] 在线 → 离线一步：对在线盘执行"离线"（默认动作离线时的卡片按钮或"全部离线"）→ 先锁定卸载全部卷并停转、再置离线属性，最终盘符消失。
- [ ] 离线 → 休眠：对已离线的盘点击顶栏"全部休眠"（默认动作为休眠时）→ 清除离线属性、保持卷锁，徽章变黄色"休眠"，盘符重新可见但访问被拒。
- [ ] 休眠 → 唤醒：点击"唤醒"→ 徽章回绿色"在线"，盘符连续存在，文件恢复可访问（首次访问可能有起转延迟，属预期，DESIGN.md 第 5 节）。
- [ ] 离线 → 唤醒：点击"唤醒"→ 清除离线属性后卷由系统自动重新挂载，盘符回来，徽章"在线"，文件可访问。
- [ ] 状态文件联动：转休眠/离线后 `state.json` 出现该盘序列号记录（Sleeping/Offline）；唤醒后记录被移除。
- [ ] 跨盘并行：两块受管盘同时对 A 点"休眠"、紧接着对 B 点"休眠"→ 两盘各自独立执行互不阻塞；同一块盘的两次操作串行排队（前一次完成前按钮禁用）。

## 3. 受限展示

- [ ] 承载启动/系统卷的磁盘（系统盘，若为机械盘）：卡片显示红色徽章"受限 · 承载启动/系统卷"，**无任何动作按钮**。
- [ ] 承载页面文件的磁盘：红色徽章"受限 · 承载页面文件"，无动作按钮。
- [ ] 动态盘/Storage Spaces 成员盘：红色徽章"受限 · 动态盘/Storage Spaces 成员"，无动作按钮。
- [ ] ATA pass-through 不可用的盘（如 Intel RST/RAID 模式拦截）：红色徽章"受限 · ATA pass-through 不可用"，无动作按钮。
- [ ] 悬停受限徽章 → 提示（ToolTip）列出全部受限原因（多条以"；"分隔）。
- [ ] 受限盘对顶栏"全部休眠/全部离线/全部唤醒"完全跳过，不产生错误与通知。
- [ ] 受限盘在托盘菜单中显示"型号（受限）"且置灰不可点。
- [ ] "新增定时策略"对话框的磁盘下拉中不出现受限盘。

## 4. 锁定失败通知（含占用进程列表）

- [ ] 制造占用：用某个程序持续占用目标盘某卷（如记事本打开该卷上的文件并保持，或资源管理器窗口停留在该卷目录内）。
- [ ] 对该盘点"休眠"→ 转换中止：卡片左下出现红字反馈"卷 X: 正被其他程序占用，无法锁定。 占用进程：<进程名列表>"；徽章保持"在线"。
- [ ] 同一时刻收到托盘通知"磁盘操作失败 · 型号"，正文含失败原因与"占用进程：…"列表（警告级）。
- [ ] 回滚验证：多卷盘上前几个卷已锁定成功、后一卷锁定失败时，此前已锁卷被自动解锁，该盘所有卷恢复可访问，磁盘未停转。
- [ ] 关闭占用程序后重试"休眠"→ 成功，徽章变"休眠"。
- [ ] 全局操作中的单盘失败：两块盘，其中一块被占用，点"全部休眠"→ 空闲盘正常进入休眠，占用盘走上述失败反馈路径，互不影响。
- [ ] 其他失败路径（如环境可复现）：卷卸载失败"卷 X: 卸载失败。"、缓存刷新失败"写入缓存刷新失败，已取消停转并回滚卷锁。"、停转命令失败"停转命令失败，已回滚卷锁。"、置离线属性失败"置离线属性失败，已回滚卷锁。"（在线→离线）或"置离线属性失败，磁盘保持休眠。"（休眠→离线）、清离线属性失败"清除离线属性失败，磁盘保持离线。"——均应有对应卡片红字 + 托盘警告通知，且状态徽章与实际一致。

## 5. 定时触发

- [ ] 设置页（左下角"设置"入口）→ "定时策略"→ 点"新增策略"→ 对话框含：磁盘下拉（仅非受限受管盘）、触发时间（TimePicker，默认 23:30）、重复星期（默认全选）、目标状态（休眠/离线单选）；"保存"写入策略并立即生效（调度器重排）。
- [ ] 未选磁盘或未勾选任何星期时"保存"按钮禁用。
- [ ] 保存后列表出现行："型号 · HH:mm · 周一、周二… → 休眠/离线"，右侧"删除"按钮。
- [ ] 成功触发：把触发时间设为 1–2 分钟后（勾选当天星期），等待到点 → 托盘通知"定时任务完成"，正文"型号 已按计划转入休眠（或离线）。"（信息级）；卡片徽章同步变化，效果与手动转换完全一致（含保护模式）。
- [ ] 锁不住跳过：到点时目标卷被程序占用 → 托盘警告通知"定时任务已跳过 · 型号"，正文含"无法锁定"原因与占用进程列表；本次不执行、不自动重试，磁盘保持在线；到下一个计划时间再次尝试。
- [ ] 磁盘消失跳过：保存策略后拔掉目标盘 → 策略行出现红字"磁盘缺失"、磁盘名退回序列号；到点通知"定时任务已跳过 · 序列号：磁盘未接入或不可管理，本次跳过，将于下次计划时间再执行。"
- [ ] 磁盘受限跳过：目标盘变为受限（如为其添加页面文件）→ 策略行红字"受限"；到点通知"定时任务已跳过 · 型号：磁盘受限，无法操作…"。
- [ ] 删除策略后到点不再触发；修改（删除+新增）后立即按新策略重排。
- [ ] 定时触发与手动操作并发时同盘串行排队，流程一致（可在计划时刻附近手动点同一盘验证不冲突）。

## 6. 开机自启

- [ ] 默认关：全新安装首次进入设置页，"开机自动启动"开关为"关"；`schtasks /Query /TN "Sleepy HDD 开机自动启动"` 提示任务不存在。
- [ ] 开→注册：把开关拨到"开"→ 任务计划程序中出现任务"Sleepy HDD 开机自动启动"：登录触发（/SC ONLOGON）、最高权限运行（/RL HIGHEST）、动作为当前 exe 完整路径（含空格时带引号）。
- [ ] 登录拉起：注销并重新登录（或重启）→ 应用自动以提权状态启动（不弹 UAC），托盘图标常驻；定时策略在无人工启动的情况下仍按计划触发。
- [ ] 关→注销：把开关拨回"关"→ 任务被删除（schtasks 查询不存在）；重启后应用不再自启。
- [ ] 注册/注销失败回滚（如环境可模拟，例如注册表/权限异常）：操作失败时开关自动拨回原状态，settings.json 不被写坏，UI 与实际注册状态一致。
- [ ] 启动校准自愈：开关为"开"时把 exe 移动到新路径并从新路径启动一次 → 任务动作路径被自动修正为新路径（schtasks 查询验证）。

## 7. 崩溃/强杀恢复

- [ ] 休眠中强杀：把某盘置休眠 → 任务管理器结束 `SleepyHDD.App.exe` → 卷锁随进程句柄关闭自动消失，盘符立即可正常访问（访问时起转）；重新启动应用 → 该盘徽章"在线"，`state.json` 中的休眠记录被清理（休眠不跨进程重启存续）。
- [ ] 离线中强杀：把某盘置离线（盘符消失）→ 任务管理器结束进程 → 重新启动应用 → 启动恢复按序列号匹配，自动清除该盘离线属性，卷重新挂载、盘符回来，徽章"在线"，记录移除。
- [ ] 离线 + 系统重启：置离线后直接强杀并重启系统 → 离线属性持久、盘符仍消失；启动应用后同样被自动上线（若开启开机自启，登录后自动完成，无需手动启动）。
- [ ] 清障失败保留记录（如可模拟）：启动时对某在案盘清离线属性失败 → 不弹异常、不阻塞启动，记录保留，下次启动自动重试。
- [ ] 在案盘已消失：强杀前有在案记录、之后拔掉该盘 → 启动后该记录被静默清理，不影响其余盘。
- [ ] 退出兜底（对照）：经托盘"退出"正常结束 → 见第 9.6 条，全部在案盘被唤醒后才退出。

## 8. 运行时缺失引导

- [ ] 准备一台未安装 Windows App Runtime 2.6.5 的干净 Windows 11 x64（self-contained 产物无需 .NET 桌面运行时，仅缺 App Runtime 即触发本场景）。
- [ ] 启动发布产物 exe → UAC 后弹出系统对话框"缺少 Windows App Runtime"，正文"Sleepy HDD 需要 Windows App Runtime 2.6.5.0 或更高版本，未在本机检测到。现在打开下载页面进行安装吗？"
- [ ] 选"是"→ 默认浏览器打开下载页 `https://aka.ms/windowsappsdk`；随后弹出"安装 Windows App Runtime"确认框"Windows App Runtime 是否已安装完成？选择"否"将退出程序。"
- [ ] 在官网安装运行时完成后选"是"→ 应用重新检测通过，正常启动进入主窗口。
- [ ] 任一环节选"否"→ 应用直接退出，不残留进程。
- [ ] 已安装运行时的机器上启动 → 完全静默，无任何对话框（见第 0 节第 3 条）。

## 9. 托盘操作

- [ ] 图标变体：全部受管盘在线 → 托盘显示常态图标；任一盘进入休眠或离线 → 切换为"睡眠"变体图标；全部唤醒后恢复常态图标。
- [ ] 双击托盘图标 → 主窗口显示并聚焦（含此前已关闭到托盘的情况）。
- [ ] 右键托盘 → 菜单结构：打开主窗口 / 分隔线 / 每盘快捷切换项（"型号：休眠"或"型号：离线"（在线盘，随默认动作）、"型号：唤醒"（休眠/离线盘）、"型号（受限）"置灰）/ 分隔线 / "全部休眠"（或"全部离线"，随默认动作）/ "全部唤醒" / 分隔线 / "退出"。
- [ ] 菜单中每盘项与全局项执行与主窗口完全相同的操作，结果实时反映到徽章与图标变体。
- [ ] 无受管磁盘时菜单每盘区显示置灰的"无受管磁盘"占位项。
- [ ] 主窗口点 X 关闭 → 窗口隐藏到托盘、进程继续运行；休眠/唤醒操作、定时触发与所有托盘通知均不受影响；双击托盘可再次打开窗口。
- [ ] 托盘"退出" → 先自动唤醒全部由本软件置为休眠/离线的在案盘（离线盘清属性、盘符回来；休眠盘解锁），再结束进程；退出后系统内所有盘可正常访问，`state.json` 记录清空。
- [ ] 修改默认动作后，托盘全局项文案与每盘在线项动作词同步变化（"全部休眠"↔"全部离线"）。
